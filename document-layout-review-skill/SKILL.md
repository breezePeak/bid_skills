# document-layout-review

这是一个**排版检查与修复工作流 Skill**。目标不是给出格式建议，而是产出经过复核的 Word。

始终执行这个闭环：

**建立基准 → 全面检查 → 形成问题清单 → 分类修复 → 重新渲染 → 验收 → 未通过则继续修复**

任何一次修改之后，都必须重新检查最终文件。不要因为脚本执行成功、DOCX 能打开或局部检查通过就宣称完成。

## 1. 建立排版基准

开始修改前先确定最终文档应遵循什么样式。

优先级：

1. 用户在当前任务中明确提出的格式要求；
2. 用户当前上传的 Word 模板；
3. 项目已经确认的模板；
4. `assets/default-template-style.json` 与 `assets/default-template.docx`；
5. 都不存在时才使用通用排版规则。

有模板时，先读取模板实际样式，不凭经验猜字体、字号、行距、标题、表格或页面设置。

如果用户上传的模板内部存在冲突，**停止修复并让用户选择**。不要替用户决定。

模板解析和冲突处理细则见 `references/template-resolution.md`。

## 2. 先检查，不要边看边改

先对整个文档建立问题清单，再开始修改。

至少检查以下 7 类：

1. **模板与真实样式使用**
   - 正文、标题、表格、题注是否真正使用了正确样式；
   - 字体、字号、粗体、行距、缩进、段前段后是否被 direct formatting 污染；
   - 页面、页眉页脚是否符合模板。

2. **标题与正文**
   - 标题层级和同级一致性；
   - 孤立标题；
   - 异常粗体、字体、字号、缩进、行距；
   - 空段、重叠、裁切、超出正文区域。

3. **表格**
   - 是否超宽；
   - 列宽是否符合内容；
   - 是否出现“一字一行”；
   - 单元格是否上下居中；
   - 表头、内边距、文字样式、跨页和重复表头是否合理。

4. **图片与流程图**
   - 是否清晰、变形、裁切、越界；
   - 流程图必须检查节点、箭头、分支、回路、标签、连线穿越、文字出框和整体可读性。

5. **页面与分节**
   - 页面尺寸、方向、页边距、分节、页眉页脚、空白页、孤立页是否正确；
   - 不允许为了塞下表格或图片擅自改变页面方向。

6. **空格**
   - 中文字符之间、中文标点旁、段首段尾、表格单元格首尾的无意义空格；
   - 不误删英文、代码、路径、URL、公式中的合法空格。

7. **标点**
   - 中文语境用全角中文标点；
   - 英文、代码、公式、命令、URL、路径用半角标点；
   - 中文引号必须是 `“……”`；
   - 禁止明显错误或重复标点。

推荐先运行 `scripts/inspect_document.py` 生成结构化检查结果，但脚本结果只是问题证据，不替代 Agent 对页面和视觉内容的判断。

## 3. 给问题分类

把问题分为三类：

### A. 可确定性自动修复
例如：模板样式未应用、错误字体/字号、整段误加粗、行距缩进错误、单元格未上下居中、明确空格和标点错误。

直接修。

### B. 需要理解内容后修复
例如：表格列宽分配、分页位置、流程图重绘、图片缩放和复杂视觉布局。

先理解内容和上下文，再修。

### C. 必须用户确认
例如：模板内部存在两个都合理但互相冲突的样式；修复可能改变业务含义；流程图原始连接关系无法确定。

停止自动选择，询问用户。

详细修复策略见 `references/repair-playbook.md`。

## 4. 修复顺序

优先按下面顺序处理，减少互相覆盖：

1. 模板/样式基准；
2. 正文、标题、字体、字号、行距、缩进；
3. 表格；
4. 图片和流程图；
5. 页面与分节；
6. 空格和标点；
7. 最终细节。

### 表格
先理解列用途，再调整列宽。长文本列应获得更多空间，短列保持紧凑。不要把“整体缩字号”作为第一修复手段。修完必须看真实页面。

### 流程图
如果原流程图是图片且存在布局问题：

**查看完整原图 → 重建节点/连线/分支/回路语义 → 校验语义 → 重新布局 → 整图重绘 → 替换回 Word → 再看最终页面**

不能只缩放、擦线或局部挪框。

### 标点和空格
只改字符本身，不为了修标点重建段落或破坏原有 run 的字体、字号、粗体、斜体。

## 5. 每轮修复后都重新检查

一轮修复完成后：

1. 检查 DOCX 结构和内容完整性；
2. 检查模板真实使用情况；
3. 检查表格/图片/流程图结构；
4. 将**最新 DOCX**重新渲染为页面图片；
5. 逐页检查最终页面。

不要检查旧截图。

## 6. 验收标准

最终交付前必须全部 PASS：

- 内容完整，没有丢字、重复、误删或改变事实；
- 模板实际样式使用正确；
- 正文和标题没有异常字体、字号、粗体、行距、缩进；
- 表格不越界、列宽自然、上下居中、跨页可读；
- 图片清晰、不变形、不裁切；
- 流程图箭头、分支和回路正确，连线清楚，文字不出框；
- 页面尺寸、方向、页边距、分节、页眉页脚正常；
- 中文/英文标点符合语境；
- 无确认出的无用空格；
- 最终页面没有肉眼可见的排版缺陷。

完整验收清单见 `references/acceptance-checklist.md`。

## 7. 验收失败就回到对应步骤

任意一项 FAIL：

1. 记录页码、对象和问题；
2. 归类到模板/正文/表格/流程图/页面/文字；
3. 回到对应修复步骤；
4. 只修改引发 FAIL 的对象；
5. 重新生成 DOCX；
6. 重新检查；
7. 重新渲染；
8. 再验收。

一直循环到全部 PASS，或遇到必须由用户确认的问题。

**最后一次修改后没有重新渲染和验收，就不能宣称完成。**

## 8. 交付

最终只向用户交付：

- 修复后的 Word；
- 简短修复摘要；
- 仍需用户确认的问题（如果有）。

不要把中间 `candidate.docx` 当最终文件，不要用“看起来应该没问题”代替验收。

只按需要加载：
