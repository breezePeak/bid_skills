# document-layout-review

## 强制执行流程

**确定模板与执行条件 → 全面检查 → 问题清单 → 分类修复 → 实际更新域 → 程序复核与重新渲染 → 逐页逐图验收 → 交付。**

不得跳过、只检查局部或提前交付。失败回到对应修复步骤；后续修改使旧验收失效。无法完成时说明具体阻塞，不把脚本成功、DOCX 能打开或记录里的 `pass` 当作最终合格。

## 1. 唯一格式基准

**固定基准：图下表上；图表原生自动编号可持续刷新，标题正常修改后不得产生域错误。模板和脚本均不得覆盖。**

**除用户明确覆盖要求及本项目已确认的例外外，全文所有对象的样式、格式和编写习惯以本次生效模板为唯一标准。待修文档只提供内容与语义结构，不提供格式标准。**

模板按“用户指定 → 项目确认 → 内置默认”选择；完整读取样式、继承、实际示例、编号、页面和页眉页脚。模板缺失、解析失败、映射不明确或多个合理约定冲突时，先确定约定，不回退使用待修文档格式。

模板的无底色、无边框、无下划线同样是标准。必须清除冲突的直接格式和继承效果，不仅复制样式名称。标题的数字形式、前后缀、分隔符、编号后空格/制表符也按模板，不能自行改成“第一章”。

本项目既有约定保持：正文黑体（黑体/SimHei）默认保留；用户明确禁止或指定替代时，通过 `text-rules.json` 覆盖。图和表各自按一级章节从 1 自动编号，显示 `图1 题名`、`表1 题名`，不拼章节前缀；这是已确认的项目编号要求，不是从待修文档推导的格式。**题注位置固定图下表上，不随模板改变。题注字体、字号、对齐和间距仍按模板。**

初检、修复、验收使用同一 `--template`、`--template-style-json`、`--text-rules`。不得让列宽、页布局或终检脚本另定字体、垂直对齐、内边距、底色等格式。属性接口与分工见 `references/template-contract.md`；文字覆盖沿用 `references/text-rules.md`。

## 2. 修改前准备

保留原始文件，使用单独工作目录。通过 `scripts/review_pipeline.py` 执行，不另拼一条缺项的交付流程。入口先检查 DOCX/模板可读性、规则绑定、工作目录、真实更新域引擎和页面渲染工具。

默认 `--field-engine auto`：有可用 Word COM 时优先使用，否则探测 LibreOffice UNO。用户明确要求 Word 时使用 `--field-engine word`，不可静默降级；LibreOffice 结果不能称为 Windows Word F9 验证。环境通过只表示能够执行，不是文档验收通过。

程序生成对象清单和内容保护计划；Agent 负责看图、确定语义、补题名及必要的定位计划，不让用户逐张填写 JSON。不得编造对象 ID、文件哈希或看图记录。先完整列出问题，再开始修改。

## 3. 全面检查八类对象

### 模板与实际格式

核对正文、各级标题、表格文字、题注、脚注、页眉页脚实际使用的样式和继承链。逐个可见文字 run 检查字体、字号、字重、斜体及本次文字要求，不按覆盖比例放过少量异常。还要检查颜色、下划线、高亮、底纹、边框和段落属性，不能因字体正确就认定格式正确。样式缺失、父样式循环或未确定的角色映射不能记为通过。

### 标题与正文

核对真实标题层级、同级一致性、段落缩进/行距/段前段后、孤立标题、异常空段、重叠、裁切和越界。封面标题、目录项、正文列表、参考文献不能当作章节标题。保留业务文字及公式上下标，不借统一格式改写内容。

### 表格

先理解表头、各列用途、内容压力和分组关系，再判断列宽；不能只检查越界。短列紧凑，长文本列有足够空间；处理一字一行、碎裂表头、突兀列宽、长 URL/路径/标识符撑宽及跨页异常。模板列宽在已允许内容适配的范围内作为基准，不机械套用，也不擅自扩大页面或旋转页面。

垂直/水平对齐、单元格内边距、表头重复、行跨页设置和文字格式以生效模板为准；不是所有模板都上下居中。默认技术标的表内首行缩进为 0，不继承正文 2 字符；其他明确模板约定按本次基准处理。

连续重复分组文字只有在属于同一对象、不会改变记录含义时才纵向合并；独立记录、状态或响应不得只因文字相同合并。合并不得丢内容、破坏行列对应或制造跨页歧义。默认模板已确认的技术偏离表为 6 个语义列、7 个物理列，技术要求包括标识列；该约定不强加给其他模板。

必须运行 `table_layout_audit.py` 并逐项处理 `review` 候选。程序建议不是自动合并指令。外观由 `template_table_style.py` 控制，模板布局由 `template_layout_contract.py` 控制，`table_layout_repair.py` 只调整几何，不顺手重设样式。

### 图片与流程图

清单覆盖图片、流程图、架构图、技术路线图和原生 Shape，不因缺少 `flowchart.json` 或箭头就漏检。先看完整原图，再放大节点文字、边界、连线和标签；无媒体文件的原生对象先渲染 Word。

文字出框、重叠、裁切、变形、不可读和连线错误必须修复。图内烧录的外部图号/题注与 Word 独立题注分开判断，不能凭整页截图误删正常图题。模板未规定的正常图片内部设计不重画；重绘时核对原有文字、节点、方向、连接、分支标签和配色，不能靠删内容解决越界。具体绘图和重绘要求继续见 `references/flowchart-drawing-standard.md`、`references/flowchart-redraw-contract.md`、`references/flowchart-rules.md`。

初检/终检使用 `figure_review.py` 逐对象清单。`flowchart_audit.py` 只验证结构数据，不证明像素内文字不出框。终检必须同时看最终图和其所在最新页面，对初检缺陷逐项关闭，不能只改 JSON 或使用旧截图。

### 页面与分节

按模板核对尺寸、方向、页边距、分节、页眉页脚、页码、空白页、孤立页及内容区域。普通图表不能靠擅自改横向或扩大纸张容纳。渲染后检查真实分页，不仅比较 XML。

### 空格

检查中文之间、中文标点周围、括号/引号内外、段首段尾、单元格首尾的无意义空格；覆盖跨 run、全角空格、NBSP、零宽脏字符。`2026 年 10 月 31 日`、`软件 1 套`等分别修成`2026年10月31日`、`软件1套`。保护英文、代码、路径、URL、公式合法空格，不能一概删除`中文 API`中的单空格。

### 标点

中文语境用全角中文标点和`“……”`；英文、代码、公式、命令、URL、路径按其语境保留半角。修复明显错误、重复标点，不改变数字的小数点、负号或代码含义。具体规则见 `references/punctuation-rules.md`、`references/whitespace-rules.md`。

### 自动编号与引用

真实标题使用模板多级自动编号和标题样式。图、表用独立 Word 题注及原生 `SEQ` 域；脚注使用原生引用和自动序号。手写数字、普通上标、把域代码写成文字不算自动编号。已有编号同时符合模板及本次要求才保留。

缺题注时根据对象和上下文补题名；装饰图、封面标志、布局表根据用途明确豁免，不乱加图号。引用先定位实际对象，再按本项目既有约定改为上下图/表；歧义引用不能糊弄成“相关图表”，文件名不能当引用。

统一使用 `numbering_repair.py`、`numbering_audit.py` 和 `template_caption_policy.py`。固定图下表上；图和表分别按一级章节从 1 递增，不显示章节前缀。可见题注使用 `SEQ 图 \* ARABIC \s 1` / `SEQ 表 \* ARABIC \s 1`，不拼 `STYLEREF`，不拿标题文字、样式名或书签充当序列参数，不逐条手工固定序号。章级重置绑定章节结构，不绑定第一张图表。

**修改标题文字、样式显示名或标题编号格式，不得损坏图表自动编号。** 修复后必须实际更新域；更新前核对域指令和边界，更新后核对当前章内序号及错误结果，禁止写入假缓存或锁域掩盖问题。修改编号相关代码时，补测标题改名、样式改名、标题编号格式改变、首张图表增删及再次更新域。Windows Word F9 验证须真实运行 Word；其他引擎结果不得冒称。见 `references/caption-baseline.md`、`references/numbering-rules.md`、`references/caption-and-image-review.md`。

## 4. 分类修复与内容保护

确定性的模板差异、错误字体/字号、空格、标点和几何问题直接修；列宽协调、分页、重复单元格分组、流程图语义需要 Agent 看内容后修；模板本身冲突、业务含义变化或图的原始关系不能确定时才要求用户确认。

优先顺序：确定基准 → 自动编号 → 文字/模板 → 表格 → 图片/流程图与页面 → 最终文字细节 → 更新域、审计、渲染。流水线中的固定步骤不要人工调换；手工局部修复后走只验收续跑，避免再次批量修复覆盖已确认的图与分页。

每阶段遵循 `references/mutation-scope-contract.md`，保护非目标对象；最终额外运行 `content_integrity.py` **直接对照原始文件**。允许规范化空格/标点、真实编号变化、计划内新题注和经原文核验的脚注搬移；业务文字、数字、URL、路径、代码、公式不得顺带修改。语义确认后的相同分组纵向合并按逻辑单元格复核，不同内容丢失仍阻断。不能把“工期30天→工期3天”解释为格式修复。

不得重置原文基准来消除差异，不得用宽泛白名单放行所有文字变化。无法识别的变更要定位、恢复或另行确认，不篡改检查报告。

## 5. 每轮修复后重新检查

**验收对象是最后保存的 Word 及其最新渲染页面，不是修复脚本的返回值。每轮修改后依次执行：**

1. **核对修改范围和内容。** 对比本轮前后文件，确认目标缺陷已改变，非目标文字、表格、图片和分节未被误改；同时按内容保护计划对照原始文件。出现误伤先撤销本轮误改，不能带着新问题继续验收。
2. **实际更新域和目录。** 用本次指定或预检选定的真实 Office 引擎更新并保存；检查图表序号、标题列表、目录、脚注及相关引用。更新失败、域结构损坏或出现错误文字，转第 7 节处理。
3. **重新执行全部必需审计。** 使用同一模板、样式约定、文字规则及原文保护计划，检查结构、实际格式、编号、文字、表格、图片清单和内容完整性。读取具体问题，不能仅凭退出码或总状态判断合格。程序未覆盖的视觉、语义问题由 Agent 检查，不能当作不存在。
4. **重新渲染最新文件。** 确认页图属于本轮最后保存的 Word，页数及页面清单完整。先复查故障页、受影响页和相邻页；最终放行前逐页检查全部最新页面，不能只看缩略拼图或沿用旧页的 PASS。
5. **逐对象闭合问题。** 表格核对列宽、跨页和分组；图片核对最终图及所在页面，必要时放大缺陷区域；逐项填写复查结果。只有实际缺陷消失且没有引入新问题，才将该项标为已解决。

**程序检查合格但页面仍有缺陷，同样 FAIL；页面看着正常但域、内容或必需审计不合格，也同样 FAIL。** 修复后走 `--audit-only` 续跑验收，不重复批量修复去覆盖已经修好的图片和分页。命令与原参数继承方法见 `references/execution-and-resume.md`。

## 6. 明确验收标准

以下标准必须同时满足。检查范围包括全文实际对象，不能只验收改过的对象；没有相应对象时确认确实不存在，不以“不适用”豁免已有问题。

| 验收对象 | 必须达到的合格标准 |
|---|---|
| 模板与实际样式 | 全文应使用的模板样式、继承关系和实际生效格式一致；没有用旧文档格式充当基准，没有未解决的角色映射或模板冲突；初检、修复和复查规则一致。 |
| 正文、标题及其他文字 | 每个可见 run 的字体、字号、字重、斜体及颜色、下划线、高亮等符合本次规则；段落对齐、行距、缩进、段间距正确。**一个确认违反规则的 run 也不放行。** 默认正文黑体例外和用户明确覆盖继续有效，公式上下标不能误清。 |
| 标题自动编号 | 真实层级与模板一致；使用原生多级列表且标题样式正确绑定，同级能续号；编号字形、前后缀、分隔符符合模板，没有手工前缀叠加、断裂列表或把目录/正文列表误当标题。 |
| 图表题注 | 每个应有题注的业务图表都有独立 Word 题注；**图下表上**；图题与图同页，表题与表格起始部分同页。图、表各自在一级章节从 1 自动递增，显示“图1 题名”“表1 题名”；无章节前缀、重复号、漏号或烧录进图片的外部题注。豁免对象用途明确。 |
| 自动编号可持续刷新 | 图表使用完整、未锁定的原生 SEQ 域；不依赖标题文字、样式显示名或书签，不拼 STYLEREF 章节号。**标题正常修改后，真实更新域不报错，序号重新计算正确。** 最后修改后已实际更新并保存；无“未定义样式”“未找到引用源”“未定义书签”等错误，无手填缓存、锁域或逐条固定重启掩盖问题。涉及编号结构修复或引擎恢复域指令时，再实际刷新一次并复核，以最后一次输出作为验收文件。 |
| 脚注与正文引用 | 脚注是原生引用及自动序号，引用与脚注内容一一对应，无漏项、重复或孤立引用；普通上标和公式指数未被误转。正文上下图/表指向实际对象，方向正确，没有用“相关图表”掩盖定位歧义。 |
| 表格宽度与可读性 | 每张表均在所在节可打印范围内；列宽同时匹配表头、列用途和内容量。短列不无必要地空旷，长列不挤成一字一行；无表头异常拆碎、无内容依据的突兀宽窄反差，长串不撑宽整表或页面。**数值未越界但肉眼明显失衡，仍不合格。** |
| 表格样式、合并与跨页 | 底色（包括无底色）、边框、文字、对齐、内边距和行规则符合本次模板；默认技术标表内首行缩进为 0。应合并的同一语义分组已正确合并，独立记录未误合并，逻辑单元格内容及行列对应无损失；表头、跨页边界和续表可读，没有异常大空白或行内容裁切。 |
| 图片与流程图 | 实际图像清晰、比例正确、不越界、不裁切；文字不出框、不重叠、不因缩放而不可读；节点、连线方向、分支、标签及分组关系完整且正确。仅改位置/大小/分页时原媒体和图内内容不变；确需重绘时已对照原图核对语义和正常风格。原图、新图及所在最终页均已看过，初检缺陷逐项关闭。 |
| 页面与分节 | 尺寸、方向、页边距、分节、页眉页脚和页码符合模板；无异常空白页、孤立标题、正文/图表/页眉页脚重叠、错位、裁切或跑出页面；分页调整没有丢失前后正文。不能为塞下图表擅自改横向或纸张。 |
| 空格与标点 | 无已确认的无意义空格、脏字符、错误或重复标点；跨 run、中文标点周边、括号/引号、日期/时间/数量单位均已核验。中英文语境正确，英文、URL、路径、代码、公式中的合法空格与符号未受损。 |
| 内容与修改范围 | 原始业务文字、数字、表格内容、图片语义及引用关系无未获允许的增删改或重复；内容保护和修改范围检查通过。不能把“工期30天→工期3天”当格式修复，不能以候选替换原文基准消除差异。 |

**最终放行条件：必需审计全部通过；未解决错误 = 0；未处理的 review/待确认项 = 0；视觉缺陷 = 0；必需但未执行的检查 = 0；最新页面、表格和图片无漏检，证据与当前文件一致。**

`review` 不等于通过。需要修改的，必须先实际修复并重新审计；确定无需修改的，记录具体对象、语义理由和最新页面复查结果。不能把“可接受”三个字当作处理结果。完整逐项清单见 `references/acceptance-checklist.md`；上述数量是验收判断条件，不要求伪造现有报告中没有的字段。

## 7. 验收失败后的处理（必须执行）

**任意一项 FAIL、漏检、未验证或证据过期，立即停止交付；不是停止解决问题。** 按下面的闭环处理：

**记录实际问题 → 定位原因与同类影响范围 → 回到对应修复步骤 → 修复并保护其他对象 → 重新保存 → 按第 5 节更新域、全量审计、重新渲染和复查 → 按第 6 节重新判定。**

### 7.1 先定位，不能只写“验收失败”

在已有问题清单中记录：对象/段落位置、页码（尚未渲染时不编造）、实际现象、应满足的标准、修复动作和复查结果。读取审计报告的具体条目及当前页图；同一缺陷可能出现多处，须查全受影响对象，不只修截图中的一个例子。

### 7.2 按失败类型返回修复

| 失败类型 | 返回哪里、具体怎么处理 |
|---|---|
| 字体、字号、颜色或段落格式不合规 | 回到第 3 节“模板与实际格式/标题与正文”，定位段落样式、字符样式及直接覆盖的实际来源，按同一规则修复全部同类异常 run/段落。不得顺手改变表格列宽、图片尺寸和分页。 |
| 表格列宽失衡、表头破碎或长串撑宽 | 回到第 3 节“表格”，读取表头和各列实际内容，重新分配可用宽度；处理长串断行及过度约束的行高。重新看整表和跨页结果，不以全表缩字号、扩大纸张或改横向绕过。底色、边框等样式不合规则另走模板表格修复。 |
| 表格合并候选未处理或合并错误 | 先核对连续行是否同一语义分组；应合并则实际合并并验证逻辑内容，不应合并则保留并记录理由。不同内容丢失或记录被误合并时恢复原有对应关系。需要修改的候选不能直接填写 `acceptable` 放行。 |
| 图片文字出框、重叠、裁切、连线错误 | 回到第 3 节“图片与流程图”，放大原图确认缺陷，修复具体文字/节点/连线，核对原有内容与风格后替换入 Word，再看新图和最终页。**图内文字出框不能靠整体缩小图片或改检查记录来消除。** |
| 原图正常，但页面放不下或缩后难以阅读 | 不重绘正常图；先保持比例调整位置和大小，仍放不下则让“图 + 图题”在模板页面内独占一页。不得删内容、拉伸图片、擅自改横向或堆空段分页；复查前后页与图题同页。 |
| 题注位置、编号或 F9 刷新错误 | 回到第 3 节“自动编号与引用”，恢复图下表上，修复真实层级/列表绑定、SEQ 指令、章节重启及实际引用关系。实际更新并检查结果；涉及编号结构或指令恢复时，再刷新一次。不得锁域、手填数字、过滤错误或把问题归结为“模板允许”。 |
| 页面、页眉页脚或分节异常 | 回到第 3 节“页面与分节”，按模板修正相关节、段落分页及对象位置，检查受影响的前后页、页码和目录；不能为了局部合格改坏其他节。 |
| 空格或标点残留/误改 | 回到第 3 节“空格/标点”，按整段可见文字定位跨 run 的具体字符，仅修相应字符，不重建整段。保护合法英文、路径、代码、公式及数字符号，随后复核文字和页面。 |
| 内容误改或非目标对象被破坏 | 撤销本轮误改，恢复到该轮修改前保留的文件或对应对象；以原始 Word 及内容计划核对，缩小修改范围后重新修。不能改原文基准、扩大白名单或删除审计问题来放行。 |
| 程序报错、更新域失败、渲染失败或证据过期 | 先读错误并修复实际原因：路径、依赖、计划定位、引擎、域结构或渲染输出。重新生成当前文件对应的完整报告和页图；不是改 `pass`、哈希或版本号。明确指定 Word 时不能静默换引擎。 |

### 7.3 修完后重验范围

每次实际修改都会使旧验收失效。目标缺陷要定点复查，同类对象和受影响的相邻页也要检查；随后执行全部必需审计，生成最新页图，完成逐页逐图终检。修好一张图不代表文字、其他表格和其他页面仍然合格。

局部修复后的续跑使用原始 `--source`、同一模板/规则、原始图片初检、原文内容保护计划和与当前对象绑定的有效计划。只验收不代替实际修复；修复由对应步骤完成后再续跑。具体命令见 `references/execution-and-resume.md`。

### 7.4 何时继续、何时停止

能确定原因并修复的，Agent 继续修，不把程序内部检查或填写记录交给用户。同一措施执行后问题仍在，必须检查它为何未生效，改用针对原因的措施；不得原样重复整条流水线，也不得因为“已经修过一轮”就放行。

只有模板存在真实冲突、业务含义/原图关系无法确定、必需源资料缺失，或排查后当前环境仍没有可执行路径时，才保留工作文件并说明具体阻塞、未完成范围及需要的确认/条件。**未解决、未验证都不是 PASS；此时不交付冒充完成的 Word。** 条件补齐后从保留的工作结果继续对应修复和验收，不重新定义原文基准。

## 8. 交付

只有第 6 节全部满足、原问题逐项闭合且没有新增缺陷，才能调用 `scripts/finalize_review.py`。入口再次核对当前文档、规则和证据；入口失败仍按第 7 节处理，不能把候选文件改名绕过。

同时交付**修复后的 Word + 简短的实际修复报告（Markdown）**。报告写清位置、原问题、实际修改和复查结果；同类批量修改可合并描述。真实验证范围和必要限制如实说明，不写未执行的 Word F9 验证，不把未生效的尝试算成已修复。正常交付不能夹带未解决的验收失败项；阻塞时只说明进展与待解决问题，不声称完成。

执行和续跑命令见 `references/execution-and-resume.md`；交付入口规则见 `references/release-gate.md`。程序负责确定性检查，Agent 负责真实语义判断与看图；记录校验不是自动视觉识别，也不等于宿主级不可绕过的交付权限。
