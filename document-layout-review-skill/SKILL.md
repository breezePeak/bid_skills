# document-layout-review

## 强制执行流程

**确定模板与全局规则 → 全文扫描并划块 → 检查当前块、列出问题 → 修复并复核当前块 → 继续下一块 → 统一更新域、程序复核、渲染与最终验收 → 交付。**

**内容块是修复单位，一两页是查看窗口。** 全文扫描用于摸底，不先做一轮全文视觉验收。每块查全问题、修复并复核后继续，最终覆盖全文；不得只修截图中的局部，也不得每完成一块就停下来等用户说“继续”。

已处理且未受影响的块不重做；返修只扩大到实际受影响范围，不因一个局部问题重新修复、渲染和检查全文。不把脚本成功、DOCX 能打开或记录里的 `pass` 当作最终合格。

## 1. 唯一格式基准

**固定基准：图下表上；图表原生自动编号可持续刷新，标题正常修改后不得产生域错误。模板和脚本均不得覆盖。**

**除用户明确覆盖要求及本项目已确认的例外外，全文所有对象的样式、格式和编写习惯以本次生效模板为唯一标准。待修文档只提供内容与语义结构，不提供格式标准。**

模板按“用户指定 → 项目确认 → 内置默认”选择；完整读取样式、继承、实际示例、编号、页面和页眉页脚。模板缺失、解析失败、映射不明确或多个合理约定冲突时，先确定约定，不回退使用待修文档格式。

模板的无底色、无边框、无下划线同样是标准。必须清除冲突的直接格式和继承效果，不仅复制样式名称。标题的数字形式、前后缀、分隔符、编号后空格/制表符也按模板，不能自行改成“第一章”。

本项目既有约定保持：正文黑体（黑体/SimHei）默认保留；用户明确禁止或指定替代时，通过 `text-rules.json` 覆盖。图和表各自按一级章节从 1 自动编号，显示 `图1 题名`、`表1 题名`，不拼章节前缀；这是已确认的项目编号要求，不是从待修文档推导的格式。**题注位置固定图下表上，不随模板改变。题注字体、字号、对齐和间距仍按模板。**

初检、修复、验收使用同一模板、模板样式约定和文字规则。不得让列宽、页布局或终检脚本另定字体、垂直对齐、内边距、底色等格式。属性分工见 `references/template-contract.md`；文字覆盖沿用 `references/text-rules.md`。

## 2. 修改前准备

保留原始文件，使用单独工作目录和一份工作文档，通过 `scripts/review_pipeline.py` 组织本流程。确认 DOCX/模板可读、规则明确、更新域和渲染工具可用。模板、共享样式、编号定义及页面设置集中确定，必要的共同设置先修正，后续不反复改动。共同设置提交前，用本次引擎做一次代表性保存检查；结果可复用，不为每块重复保存样例。样例检查不代替最终文件验收。

**默认渲染和更新域顺序固定为 Microsoft Word → WPS Writer → LibreOffice。** 只有前一个引擎未安装、不可调用、超时或实际操作失败，才尝试下一个；成功即停止。用户明确指定引擎时不静默降级。文档域结构、内容或视觉检查失败必须修复，不能通过换引擎掩盖。

以当前环境实际可调用的软件为准，不把用户电脑已安装等同于远程可用。记录实际引擎和切换原因；WPS/LibreOffice 结果不得冒称 Word F9 验证。保存成功与退出、临时文件清理结果分开处理：输出完整且校验有效时保留成果，清理失败只处理清理，不重做全文。无可用引擎时说明阻塞，不交付未验收候选。能力和限制见 `references/rendering-engines.md`。

扫描全文标题、正文、表格、图片、题注、脚注、页眉页脚和分节，列出对象及共同问题。**先摸底，不先把全文所有对象修复一遍。** 按文档顺序划块：

- **正文块：** 一个短小节或一组连续段落，查看时以一两页左右为宜；标题与后文开头一起处理，不把标题单独留在块末。
- **表格块：** 整张表及其题注一起处理，不按页拆表。跨页长表分窗口阅读全部内容，但列宽、分组和表格规则统一判断。
- **图片块：** 图片、流程图或原生 Shape 与题注一起处理，查看必要的前后衔接；表内图片随所属表格检查，不从表中拆出另排。

按实际段落和对象定位块，不只记页码。脚注随引用检查，页眉页脚和分节按所属节检查，不得漏掉正文块外对象。**不拆成多份 Word 分别修复再合并。**

程序负责定位和内容保护；Agent 负责语义、看图及缺失题名，不让用户填写内部记录。使用宿主已授权的视觉能力，不擅自发送给新服务，不编造结果；处理到含图块再看图，不先等待全文图片检查完成。自动视觉接口不可用时，使用宿主看图工具查看程序导出的实际视图并保留调用记录；两种方式都不可执行时才保留待检查。

## 3. 全面检查八类对象

**按块检查以下八类对象，不按类别反复扫修全文。** 当前块没有的对象不执行对应修复；当前块已有的对象必须查全。正常对象保持不动，明确不合规的格式直接按模板修正。

### 模板与实际格式

核对正文、各级标题、表格文字、题注、脚注、页眉页脚实际使用的样式和继承链。由程序逐个可见文字 run 检查字体、字号、字重、斜体及本次文字要求，不按覆盖比例放过少量异常。还要检查颜色、下划线、高亮、底纹、边框和段落属性，不能因字体正确就认定格式正确。样式缺失、父样式循环或未确定的角色映射不能记为通过。

### 标题与正文

核对真实标题层级、同级一致性、段落缩进/行距/段前段后、孤立标题、异常空段、重叠、裁切和越界。封面标题、目录项、正文列表、参考文献不能当作章节标题。保留业务文字及公式上下标，不借统一格式改写内容。

### 表格

先理解表头、各列用途、内容压力和分组关系，再判断列宽；不能只检查越界。短列紧凑，长文本列有足够空间；处理一字一行、碎裂表头、突兀列宽、长 URL/路径/标识符撑宽及跨页异常。模板列宽在已允许内容适配的范围内作为基准，不机械套用，也不擅自扩大页面或旋转页面。

垂直/水平对齐、单元格内边距、表头重复、行跨页设置和文字格式以生效模板为准；不是所有模板都上下居中。默认技术标的表内首行缩进为 0，不继承正文 2 字符；其他明确模板约定按本次基准处理。

连续重复分组文字只有在属于同一对象、不会改变记录含义时才纵向合并；独立记录、状态或响应不得只因文字相同合并。合并不得丢内容、破坏行列对应或制造跨页歧义。默认模板已确认的技术偏离表为 6 个语义列、7 个物理列，技术要求包括标识列；该约定不强加给其他模板。

使用表格审计结果，逐项处理当前表的 `review` 候选。程序建议不是自动合并指令。外观按模板表格规则修复，列宽修复只调整几何，不顺手重设样式；已经协调的列宽不重新分配。同一张跨页表按整表检查和修复，不因切换查看页面反复调整。

### 图片与流程图

清单覆盖正文及页眉页脚、脚注尾注中的图片、流程图、架构图、技术路线图和原生 Shape，不因缺少 `flowchart.json`、箭头或专用重绘脚本就漏检。清点完成不等于看图通过；没有缺陷记录也不等于图片正常。**处理到含图块时，先看完整原图，再放大节点文字、边界、连线和标签；侧栏、竖框和外围说明也必须检查。** 无媒体文件的原生对象通过实际渲染查看，不以无法提取图片为由豁免。

文字出框、重叠、裁切、变形、不可读和连线错误必须修复。图内烧录的外部图号/题注与 Word 独立题注分开判断，不能凭整页截图误删正常图题。模板未规定的正常图片内部设计不重画；进入修图前先确认具体对象、真实缺陷和修改范围，无缺陷依据不开始重画。重绘时核对原有文字、节点、方向、连接、分支标签和配色，不能靠删内容解决越界。具体绘图和重绘要求见 `references/flowchart-drawing-standard.md`、`references/flowchart-redraw-contract.md`、`references/flowchart-rules.md`。

每张图必须实际看过完整图及足以判断文字和边界的局部视图，逐个文字块对照所属框四边；不能只看整页缩略图或图的中心。`flowchart_audit.py` 只验证结构数据，不证明文字不出框。不能用手填 `pass` 代替实际看图。

**修图后先复查当前图，放回文档后的尺寸、分页和图题关系在对应页面核对；正常图不固定执行多轮盲检。** 已检查且图内内容未变时，不重复图内检查；最终所在页面仍须有有效的页面检查结果。发现问题或结果不确定时，只针对相关图补充放大、修复和复查，不重新检查全文所有图片。

初检通过不代表永远没有缺陷。后续新发现必须登记并修复，不覆盖原始观察；图内缺陷已登记但图像未实际改变，不能用后来一次 PASS 消除。原图、修改后的图及最终页面缺少必要检查时，保留待查，不宣称合格。

### 页面与分节

按模板核对尺寸、方向、页边距、分节、页眉页脚、页码、空白页、孤立页及内容区域。普通图表不能靠擅自改横向或扩大纸张容纳。块内检查前后衔接，最终根据最新渲染检查真实分页，不仅比较 XML。

### 空格

检查中文之间、中文标点周围、括号/引号内外、段首段尾、单元格首尾的无意义空格；覆盖跨 run、全角空格、NBSP、零宽脏字符。`2026 年 10 月 31 日`、`软件 1 套`等分别修成`2026年10月31日`、`软件1套`。保护英文、代码、路径、URL、公式合法空格，不能一概删除`中文 API`中的单空格。

### 标点

中文语境用全角中文标点和`“……”`；英文、代码、公式、命令、URL、路径按其语境保留半角。修复明显错误、重复标点，不改变数字的小数点、负号或代码含义。具体规则见 `references/punctuation-rules.md`、`references/whitespace-rules.md`。

### 自动编号与引用

真实标题使用模板多级自动编号和标题样式。图、表用独立 Word 题注及原生 `SEQ` 域；脚注使用原生引用和自动序号。手写数字、普通上标、把域代码写成文字不算自动编号。已有编号同时符合模板及本次要求时保留，不重复重建。

缺题注时根据对象和上下文补题名；装饰图、封面标志、布局表根据用途明确豁免，不乱加图号。引用先定位实际对象，再按本项目既有约定改为上下图/表；歧义引用不能糊弄成“相关图表”，文件名不能当引用。

使用统一的编号与题注规则。固定图下表上；图和表分别按一级章节从 1 递增，不显示章节前缀。可见题注使用 `SEQ 图 \* ARABIC \s 1` / `SEQ 表 \* ARABIC \s 1`，不拼 `STYLEREF`，不拿标题文字、样式名或书签充当序列参数，不逐条手工固定序号。章级重置绑定章节结构，不绑定第一张图表。

**修改标题文字、样式显示名或标题编号格式，不得损坏图表自动编号。** 当前块先修正域指令、边界、层级和引用；全部块完成后统一实际更新域并检查结果，不为每块单独刷新全文目录。涉及编号结构修复或引擎恢复域指令时，须验证再次刷新仍正确。禁止写入假缓存或锁域掩盖问题。Windows Word F9 验证须真实运行 Word；其他引擎结果不得冒称。见 `references/caption-baseline.md`、`references/numbering-rules.md`、`references/caption-and-image-review.md`。

## 4. 分类修复与内容保护

确定性的模板差异、错误字体/字号、空格、标点和几何问题直接修；列宽协调、分页、重复单元格分组、流程图语义需要 Agent 看内容后修；模板本身冲突、业务含义变化或图的原始关系不能确定时才要求用户确认。

**每块按“检查 → 问题清单 → 针对性修复 → 复核 → 下一块”推进。** 块内按依赖处理标题题注、文字样式、表格、图片和局部布局；正常项目不动，不对每个块重复运行全文批量修复。

修复只作用于目标对象：改正文样式不顺手改列宽或图片，修图不重建全文编号。确需改共享样式或页面设置时，先确定影响范围，不把全局改动当作局部修复。

每块遵循 `references/mutation-scope-contract.md`，保护非目标对象；最终额外运行内容完整性检查，**直接对照原始文件**。允许规范化空格/标点、真实编号变化、计划内新题注和经原文核验的脚注搬移；业务文字、数字、URL、路径、代码、公式不得顺带修改。语义确认后的相同分组纵向合并按逻辑单元格复核，不同内容丢失仍阻断。不能把“工期30天→工期3天”解释为格式修复。

不得重置原文基准来消除差异，不得用宽泛白名单放行所有文字变化。无法识别的变更要定位、恢复或另行确认，不篡改检查报告。只记录已处理块、待处理问题和下一位置；中断后从保留的工作文档继续，不清空进度重修全文。

## 5. 每轮修复后重新检查

**当前块修复后复核当前块，全部块完成后统一验收全文。验收对象是实际保存的 Word 及其最新渲染结果，不是修复脚本的返回值。**

### 5.1 当前块修复后的复核

1. **核对修改范围和内容。** 确认本块缺陷已改变，非目标文字、表格、图片和分节未被误改；按原文内容保护要求核对。出现误伤先撤销误改，不能带着新问题继续。
2. **复查本块实际结果。** 格式、文字和域结构由程序在采纳拟稿前核对，不合格就拒绝拟稿并留在当前块；表格核对整表列宽、分组和内容，图片实际改变后须先完成新图复查，不能以哈希变化代替修好。失败继续修本块，不重复修已通过的其他块。
3. **检查必要的页面衔接。** 需要判断实际分页时查看受影响页面及相邻边界。支持局部渲染时使用实际局部能力；只能全文导出时合并需要渲染的检查，不为每个块固定重新导出整本文档。尚未查看的分页效果留待统一验收，不能提前填写通过。
4. **保存结果并继续下一块。** 本块修复完成不等于整份文档最终通过。保留尚需最终页面确认的项目，不因这类统一验收项重复修本块，也不遗漏它们。

### 5.2 全部块完成后的统一验收

**实际更新域和目录 → 全文必需程序审计 → 渲染最新文档 → 逐页检查全部最终页面及图表。** 这是一轮最终验收，不是重新执行全文修复。

实际更新并保存后，先核对保存前后真实生效的格式，再检查图表序号、标题列表、目录、脚注和引用。等效序列化和界面元数据变化不反复修，真正的字体、字距、分页及模板差异仍须修复；不能把保存结果反过来定义为模板。随后按同一模板、文字规则及原文基准审计结构、格式、文字、图表和内容完整性。读取具体问题，不仅看退出码。

确认渲染属于最后保存的文档且页面完整。按一两页窗口检查所有最终页面，整表和图题保持整体判断；不能只看缩略拼图，不能把格式通过当作页面通过。

终检失败项集中返回对应块修复，**不重跑全文修复，不对正常图表重复盲检。** 再次渲染后复查变化页面、受影响边界及相关对象；内容、规则和页面效果经核对未变时，复用有效结果，不改写旧记录冒充新检查。

**程序检查合格但页面仍有缺陷，同样 FAIL；页面看着正常但域、内容或必需审计不合格，也同样 FAIL。** 同一文件和执行条件未变时继续已有验收任务，不无故再启动一轮更新域、审计和渲染。

## 6. 明确验收标准

以下标准必须同时满足。检查范围包括全文实际对象，不能只验收改过的对象；没有相应对象时确认确实不存在，不以“不适用”豁免已有问题。块内逐项复核，依赖最终分页和域更新的项目在统一验收时确认，不提前判为通过。

| 验收对象 | 必须达到的合格标准 |
|---|---|
| 模板与实际样式 | 全文应使用的模板样式、继承关系和实际生效格式一致；没有用旧文档格式充当基准，没有未解决的角色映射或模板冲突；初检、修复和复查规则一致。 |
| 正文、标题及其他文字 | 每个可见 run 的字体、字号、字重、斜体及颜色、下划线、高亮等符合本次规则；段落对齐、行距、缩进、段间距正确。**一个确认违反规则的 run 也不放行。** 默认正文黑体例外和用户明确覆盖继续有效，公式上下标不能误清。 |
| 标题自动编号 | 真实层级与模板一致；使用原生多级列表且标题样式正确绑定，同级能续号；编号字形、前后缀、分隔符符合模板，没有手工前缀叠加、断裂列表或把目录/正文列表误当标题。 |
| 图表题注 | 每个应有题注的业务图表都有独立 Word 题注；**图下表上**；图题与图同页，表题与表格起始部分同页。图、表各自在一级章节从 1 自动递增，显示“图1 题名”“表1 题名”；无章节前缀、重复号、漏号或烧录进图片的外部题注。豁免对象用途明确。 |
| 自动编号可持续刷新 | 图表使用完整、未锁定的原生 SEQ 域；不依赖标题文字、样式显示名或书签，不拼 STYLEREF 章节号。**标题正常修改后，真实更新域不报错，序号重新计算正确。** 最后修改后已实际更新并保存；无“未定义样式”“未找到引用源”“未定义书签”等错误，无手填缓存、锁域或逐条固定重启掩盖问题。涉及编号结构修复或引擎恢复域指令时，再实际刷新一次并复核，以最后一次输出作为验收文件。 |
| 脚注与正文引用 | 脚注是原生引用及自动序号，引用与脚注内容一一对应，无漏项、重复或孤立引用；普通上标和公式指数未被误转。正文上下图/表指向实际对象，方向正确，没有用“相关图表”掩盖定位歧义。 |
| 表格宽度与可读性 | 每张表均在所在节可打印范围内；列宽同时匹配表头、列用途和内容量。短列不无必要地空旷，长列不挤成一字一行；无表头异常拆碎、无内容依据的突兀宽窄反差，长串不撑宽整表或页面。**数值未越界但肉眼明显失衡，仍不合格。** |
| 表格样式、合并与跨页 | 底色（包括无底色）、边框、文字、对齐、内边距和行规则符合本次模板；默认技术标表内首行缩进为 0。应合并的同一语义分组已正确合并，独立记录未误合并，逻辑单元格内容及行列对应无损失；表头、跨页边界和续表可读，没有异常大空白或行内容裁切。 |
| 图片与流程图 | 实际图像清晰、比例正确、不越界、不裁切；文字不出框、不重叠、不因缩放而不可读；节点、连线方向、分支、标签及分组关系完整且正确。仅改位置/大小/分页时原媒体和图内内容不变；确需重绘时已对照原图核对语义和正常风格。完整图及必要局部、四周边界和最终页面均有实际检查，初检及后续新发现缺陷逐项关闭；未变化的有效结果可以复用，不以固定检查次数代替实际合格。 |
| 页面与分节 | 尺寸、方向、页边距、分节、页眉页脚和页码符合模板；无异常空白页、孤立标题、正文/图表/页眉页脚重叠、错位、裁切或跑出页面；分页调整没有丢失前后正文。不能为塞下图表擅自改横向或纸张。 |
| 空格与标点 | 无已确认的无意义空格、脏字符、错误或重复标点；跨 run、中文标点周边、括号/引号、日期/时间/数量单位均已核验。中英文语境正确，英文、URL、路径、代码、公式中的合法空格与符号未受损。 |
| 内容与修改范围 | 原始业务文字、数字、表格内容、图片语义及引用关系无未获允许的增删改或重复；内容保护和修改范围检查通过。不能把“工期30天→工期3天”当格式修复，不能以候选替换原文基准消除差异。 |

**最终放行条件：全文内容块无漏检；必需审计全部通过；未解决错误 = 0；未处理的 review/待确认项 = 0；视觉缺陷 = 0；必需但未执行的检查 = 0；最新页面、表格和图片均有有效检查结果。**

`review` 不等于通过。需要修改的，必须实际修复并复核；确定无需修改的，记录具体对象、语义理由和页面复查结果。不能把“可接受”三个字当作处理结果。完整逐项清单见 `references/acceptance-checklist.md`；上述数量是验收判断条件，不要求伪造报告字段。

## 7. 验收失败后的处理（必须执行）

**任意一项 FAIL、漏检、未验证或结果过期，停止交付并返回受影响块；不是从头重修全文，也不是停止解决问题。**

**记录实际问题 → 定位所属块和影响范围 → 修复具体对象并保护其他内容 → 复核当前块及受影响边界 → 继续未完成工作 → 按第 5、6 节完成最终验收。**

### 7.1 先定位，不能只写“验收失败”

在已有问题清单中记录：对象/段落位置、页码（尚未渲染时不编造）、实际现象、应满足的标准、修复动作和复查结果。读取审计条目及相关页图；同一缺陷出现多处时定位全部受影响块，分别处理，不能只修截图中的一个例子，也不能借同类排查重修无关对象。

### 7.2 按失败类型返回修复

| 失败类型 | 返回哪里、具体怎么处理 |
|---|---|
| 字体、字号、颜色或段落格式不合规 | 回到对应块，定位段落样式、字符样式及直接覆盖的实际来源，按第 3 节规则修复相关异常 run/段落；同类异常定位到其他块后分别处理。不得顺手改变表格列宽、图片尺寸和分页。 |
| 表格列宽失衡、表头破碎或长串撑宽 | 回到对应表格块，读取表头和各列实际内容，重新分配可用宽度；处理长串断行及过度约束的行高。重新看整表和跨页结果，不以全表缩字号、扩大纸张或改横向绕过。底色、边框等样式不合规则按模板另行修正。 |
| 表格合并候选未处理或合并错误 | 在对应整表内核对连续行是否同一语义分组；应合并则实际合并并验证逻辑内容，不应合并则保留并记录理由。不同内容丢失或记录被误合并时恢复原有对应关系。需要修改的候选不能直接填写 `acceptable` 放行。 |
| 图片文字出框、重叠、裁切、连线错误 | 回到对应图片块，放大原图确认缺陷，修复具体文字/节点/连线，核对原有内容与风格后替换入 Word，再看新图和相关页面。**图内文字出框不能靠整体缩小图片或改检查记录来消除。** |
| 原图正常，但页面放不下或缩后难以阅读 | 不重绘正常图；先保持比例调整位置和大小，仍放不下则让“图 + 图题”在模板页面内独占一页。不得删内容、拉伸图片、擅自改横向或堆空段分页；复查前后页与图题同页。 |
| 题注位置、编号或 F9 刷新错误 | 回到对应标题或图表块，恢复图下表上，修复真实层级/列表绑定、SEQ 指令、章节重启及引用关系。涉及共享编号定义时检查相关章节；修复集中完成后实际刷新并核对，必要时再次刷新。不得锁域、手填数字、过滤错误或把问题归结为“模板允许”。 |
| 页面、页眉页脚或分节异常 | 修正对应节、段落分页及对象位置，检查受影响的前后页、页码和目录；不能为了局部合格改坏其他节。分页影响延伸到后文时按实际范围复查，不机械限定两页。 |
| 空格或标点残留/误改 | 在对应块按整段可见文字定位跨 run 的具体字符，仅修相应字符，不重建整段。保护合法英文、路径、代码、公式及数字符号，随后复核文字和受影响页面。 |
| 内容误改或非目标对象被破坏 | 撤销误改，恢复对应对象；以原始 Word 核对后缩小修改范围重修。不得通过恢复整份旧文档丢掉其他块已完成的正确修改，不改原文基准、不扩大白名单、不删除审计问题。 |
| 程序报错、更新域失败、渲染失败或结果过期 | 先修复实际原因：路径、依赖、对象定位、引擎、域结构或渲染输出。继续失败步骤，补齐当前文件的有效检查结果；不重跑已经完成的修复，不改 `pass`、哈希或版本号。明确指定 Word 时不能静默换引擎。 |

### 7.3 修完后重验范围

**最终文档再次修改后，原交付结论失效；未受影响块的修复结果不因此全部失效。** 复查目标对象、实际受影响的其他对象和页面衔接。只是页码变化时重新确认位置及页面效果，不重做已经正确的文字、表格或图片内容。

后续新发现追加到原问题清单，不覆盖初检；已发现的图内问题未实际修图时不得被后续 PASS 消除。同一轮终检的失败项集中返修，再统一更新域、程序复核和渲染；新结果中的变化页面及相关对象重新检查，经核对未变化的有效结果保留。

续跑始终沿用原始文件、同一模板与规则、原始图片及内容保护基准，从当前工作文档恢复对应块或最终验收步骤。不能把候选重新当作原文，也不能为了继续执行而清空未解决问题。

### 7.4 何时继续、何时停止

能确定原因并修复的，Agent 继续修，不把程序内部检查或填写记录交给用户。相同输入和执行条件连续两次出现相同终检错误时，不再执行第三次全文重试，先定位并改变真正的原因；改文件名、重打包、换工作目录或填写新的说明不算修复。能独立处理的其他块可以继续，失败项不得放行。保存往返反复产生同一差异时，修正保存方式或准确的属性比较，不循环“清除属性—保存—再清除”。

只有模板存在真实冲突、业务含义/原图关系无法确定、必需源资料缺失，或排查后当前环境仍没有可执行路径时，才保留工作文件并说明具体阻塞、未完成范围及需要的确认/条件。**未解决、未验证都不是 PASS；此时不交付冒充完成的 Word。** 条件补齐后从保留的块进度继续，不重新定义原文基准。

## 8. 交付

只有第 6 节全部满足、原问题逐项闭合且没有新增缺陷，才能调用 `scripts/finalize_review.py`。入口核对当前文档、规则和有效检查结果；失败按第 7 节处理，不能把候选文件改名绕过。

同时交付**修复后的 Word + 简短的实际修复报告（Markdown）**。报告写清位置、原问题、实际修改和复查结果；同类批量修改可合并描述。图片逐个区分未检查、检查正常、已修复和仍有问题，不把对象清单通过概括为图片通过。实际渲染引擎、切换原因、真实验证范围和必要限制如实说明，不写未执行的 Word F9 验证，不把未生效的尝试算成已修复。正常交付不能夹带未解决的验收失败项；阻塞时只说明进展与待解决问题，不声称完成。

本页规定执行顺序、修复单位及复查范围；`references/` 提供对应对象的详细检查和修复规则。程序负责确定性检查，Agent 负责真实语义判断与看图；不能以记录齐全代替实际合格。
