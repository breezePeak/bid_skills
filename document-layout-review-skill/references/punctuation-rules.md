# 标点语境规则

核心原则只有两条：

1. **写中文文章：使用全角中文标点。**
2. **写英文、代码、公式：使用半角标点。**

不要再使用“所有技术符号一律半角”这种全局规则。必须先判断当前文字属于中文语境，还是英文／代码／公式语境。

## 1. 中文语境

中文正文、中文标题、中文表格文字、中文图题、中文流程图节点和中文分支标签使用全角中文标点，例如：

- `，。；：？！`
- `（）`
- `“”‘’`
- 中文并列或二选一可使用 `、` 或 `／`
- 中文省略号使用 `……`

示例：

```text
满足条件?   → 满足条件？
否,整改      → 否，整改
(测试阶段)  → （测试阶段）
"技术路线"  → “技术路线”
复测/回归    → 复测／回归
```

## 2. 英文语境

英文句子、英文标题、英文说明、英文标识组成的独立短语使用半角标点，例如：

```text
Hello，world！   → Hello,world!
API（v1.2）      → API(v1.2)
status：ok       → status: ok
```

不要把英文里的 `, . ; : ? ! ( ) " '` 自动改成中文全角标点。

## 3. 代码、命令、路径、URL、配置和公式

这些内容按技术语法处理，统一保留或修正为半角标点／运算符：

- URL、URI、邮箱；
- Windows／Unix 路径；
- 源代码、命令行；
- JSON、YAML、XML；
- 版本号、小数、IP 地址；
- 函数名、变量名、接口名；
- 数学公式、逻辑表达式、比较表达式。

示例：

```text
f（x）＝x＋1      → f(x)=x+1
A＜B              → A<B
https：//a.com    → https://a.com
x＋y＝10          → x+y=10
```

## 4. 中英文混排

混排内容不能按整段“一刀切”。按局部语境判断：

```text
系统返回“成功”，API(v1.2)继续执行。
```

其中中文句法仍使用中文标点；`API(v1.2)` 内部是英文／版本表达，使用半角括号和句点。

如果程序无法可靠判断局部语境，只报告问题，不做破坏性的全局替换。

## 5. DOCX 审计与修复

统一使用上下文脚本：

```bash
python3 scripts/contextual_punctuation.py input.docx --json-out punctuation-audit.json
```

需要修复时：

```bash
python3 scripts/contextual_punctuation.py input.docx --out repaired.docx --json-out punctuation-repair.json
```

旧入口 `scripts/chinese_punctuation.py` 仅作为兼容入口，内部调用同一套上下文规则。

## 6. 完成门槛

最终文档不能存在明确的语境冲突：

- 中文文章中仍使用半角英文句读标点；
- 英文、代码或公式中仍使用全角中文标点／全角运算符。

混合语境无法确定时可以保留 warning，但不能把不确定内容机械替换。
