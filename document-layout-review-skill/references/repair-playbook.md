# 修复策略

## 基本原则

- 只修问题对象；
- 不改变事实、数字和业务含义；
- 确定性问题优先使用确定性方法；
- 视觉问题必须看最终页面；
- 任何修复后重新验收。

## 正文/标题

优先恢复正确的模板 style，再清除覆盖样式的错误 direct formatting。不要重新创建整段文字。

## 表格

1. 判断每列用途和内容压力；
2. 获取页面可用宽度；
3. 给短列设合理最小宽度；
4. 把剩余宽度优先分给长文本列；
5. 同步写入 tblGrid、tcW 等实际宽度；
6. 统一模板要求的字体、字号、行距、单元格内边距和垂直对齐；
7. 设置必要的重复表头；
8. 渲染检查。

禁止靠“整体缩小字体”“改横向页面”掩盖不合理列宽。

## 流程图

先看全图。无法理解全图时不要重绘。

重建：
- 节点；
- 节点类型；
- 文本；
- from/to；
- 分支标签；
- 汇合；
- 回路；
- 主方向。

校验语义后用可靠图布局引擎重新排版。必须避免：
- 线穿节点；
- 箭头指错；
- 歧义交叉；
- 分支标签错线；
- 文字出框；
- 图过小。

## 页面

先修内容布局，再修页面。除非模板或用户要求，不要通过切换横向解决局部表格问题。

## 标点/空格

按段落语境判断，尽量原位替换字符，保持原 run 格式。不能确认时不自动改。
