# 修复策略

## 基本原则

- 只修问题对象；
- 不改变事实、数字和业务含义；
- 确定性问题优先使用确定性方法；
- 视觉问题必须看最终页面；
- 任何修复后重新验收。

## 正文/标题

优先恢复正确的模板 style，再清除覆盖样式的错误 direct formatting。不要重新创建整段文字。

## 表格

表格不能采用“看见窄列就随便拉宽”的方式修。先分析，再整体分配。

1. 识别表头和每列用途，标记 compact / medium / narrative 等语义角色；
2. 获取当前节可打印宽度，作为整表硬上限；
3. 统计每列表头长度、正文平均内容量、较长内容和最长内容；
4. 给短列设置能够正常阅读表头和正文的最小宽度；
5. 将剩余宽度按内容压力分给中等列和长文本列；
6. 检查相邻列是否存在无依据的极端宽窄反差；
7. 检查长 URL、路径、版本号、哈希、英文标识等不可断行内容，禁止让 autofit 把表格或页面拉宽；
8. 检查连续重复分组列：
   - 若“标的名称/项目名称/工作对象/类别/阶段/模块/工作包”等连续多行属于同一语义对象，则纵向合并；
   - 若各行是独立记录、独立状态或独立响应，则保持分开；
   - 无法判断是否会改变业务含义时，交给用户确认；
9. 合并后保持其他列与原行一一对应，不得丢内容或错位；
10. 同步写入稳定的 `tblGrid`、`tcW`、表格总宽度、单元格内边距、水平/垂直对齐和重复表头；
11. 重新运行 `table_layout_audit.py`；
12. 渲染真实页面，检查列宽是否协调、合并是否自然、跨页是否正常。

模板中的同表头列宽比例只能作为参考。如果当前正文内容明显不同，必须按当前内容重新平衡。

禁止靠以下方式掩盖问题：

- 整体缩小字号；
- 擅自改横向页面；
- 保留明显失衡的旧模板列宽；
- 因为两个单元格文字相同就机械合并；
- 只修改 `tblGrid` 却不更新实际单元格宽度。

## 流程图

先看全图。无法理解全图时不要重绘。

重建：
- 节点；
- 节点类型；
- 文本；
- from/to；
- 分支标签；
- 汇合；
- 回路；
- 主方向。

校验语义后用可靠图布局引擎重新排版。必须避免：
- 线穿节点；
- 箭头指错；
- 歧义交叉；
- 分支标签错线；
- 文字出框；
- 图过小。

## 页面

先修内容布局，再修页面。除非模板或用户要求，不要通过切换横向解决局部表格问题。

## 标点/空格

按段落语境判断，尽量原位替换字符，保持原 run 格式。不能确认时不自动改。
