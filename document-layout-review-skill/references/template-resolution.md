# 模板解析与冲突处理

## 目标

模板是最终排版的样式来源，不是只用于“参考外观”的图片。

## 无用户模板

直接读取：

- `assets/default-template.docx`
- `assets/default-template-style.json`

默认样式 JSON 是已经人工确认的固定基线，不需要每次重新解释。

## 用户上传模板

1. 读取模板真实 OOXML 样式；
2. 提取正文、标题、表格、题注、页面、页眉页脚、编号和主题字体；
3. 检查直接格式是否与命名样式冲突；
4. 检查同用途是否存在多套不一致样式；
5. 输出冲突列表。

如果没有冲突，生成本次任务的 resolved style profile。

如果有冲突，必须让用户选择。冲突项至少说明：

- 冲突对象；
- 方案 A；
- 方案 B；
- 两种方案分别来自模板哪里；
- 选择后会影响什么。

禁止模型自行采用“推荐项”。

## 样式落实

有模板时最终 Word 必须**实际使用模板样式**。仅保证 `styles.xml` 还存在不算通过。

必须同时检查：

- 段落 styleId；
- run 上的直接字体、字号、粗体、斜体；
- 表格和题注样式；
- 页面设置；
- 模板主题字体是否被直接格式覆盖。

当 direct formatting 明显污染整段时，可清除污染并恢复模板；局部明确强调不要误删。
