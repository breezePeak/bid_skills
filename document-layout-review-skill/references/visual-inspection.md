# 按块看图与最终页面核验

## 硬约束：图片必须由视觉大模型实际看过

每张业务图片、流程图、架构图、技术路线图和原生 Shape，至少必须有一次把**真实图片字节**及必要完整/局部视图直接送入具备视觉能力的大模型。OCR、文字转录、像素检测、边框脚本、对象清单、整页缩略图、确定性门禁或人工填写 `pass` 都不能替代大模型看图，也不能产生图片视觉 PASS。

有效图片回执必须同时绑定：当前图片/裁片哈希、实际 provider/model、真实调用记录、本次全部 image id、逐视图观察及六项检查结果。`inspection=null`、`view_bundle=null`、模型身份缺失、任一项 `pending/uncertain`、模型未确认看完全部 image id、哈希过期，都等于**未检查**，必须保持阻断。

## 必须检查的内容

处理到含图块时看完整原图、重叠局部及四周边界，逐个文字块对照所属框。侧栏、竖框、外围说明不能漏掉。没有箭头不能豁免文字边界；原生 Shape 不能因为没有媒体文件而漏检。

文字出框、重叠、裁切、不可读、连接/分组错误和图内烧录外部题注必须定位并修复。Word 中独立图题不属于图内烧录内容。修改后先看实际新图，语义、配色及正常风格对照原图；最终还要核对所在页面、尺寸、分页和图题关系。

## 执行方式

优先使用已授权的视觉大模型适配器；未配置适配器时，自动生成 `awaiting_host_visual_model` 任务，使用宿主自身的视觉大模型。`visual_evidence.py` 将真实图片字节送入模型，不以路径、OCR 文本或假回执代替图片。`--vision-worker-config worker.json` 指定命令配置；配置必须声明 `reviewer.kind=vision_model`，并给出实际 provider/model（可用 `model_env` 从环境变量解析）。可选 HTTP 适配器的环境变量仍为 `DLR_VISION_API_URL`、`DLR_VISION_MODEL`、`DLR_VISION_API_KEY`。没有默认外部服务，不自动发送投标资料给新供应商。

初检按当前块触发，一次真实视觉大模型调用覆盖当前图的必要视图。正常图不预先等待全文图片检查。终检协议为 `dlr-visual-v3`；图片像素或需要重新核验的页面上下文改变时执行当前对象检查，有不确定或未修复问题就失败。

程序可做像素、哈希、结构或边界辅助筛查，但它的结果只有两种用途：**提示模型重点检查**或**验证证据绑定**。程序未报错绝不等于视觉通过。

## 允许复用什么

**图内未变，位置可能变：** 原图已有真实视觉大模型初检通过证据、当前媒体归一化像素一致、没有已登记缺陷，并且所在的当前页面已有实际观察结果时，允许复用图内证据。记录明确标成 `unchanged-content-current-pages`，不是伪造一次新的模型调用。当前页面没有通过，图内通过不能替代页面验收。

**图和所在页均未变：** 当前对象、原图、规则及页面哈希全部匹配时，已有真正通过的最终图片检查可复用，原始请求/响应和模型身份不改写。

**不能复用：** 从未有真实视觉大模型回执；图片修改；原生 Shape 渲染裁片变化；页面效果变化且缺少当前观察；初检失败或不确定；后续缺陷未闭合；规则改变；回执过期。`未修改`、`无需处理`、`脚本全绿`、`整页看着正常`均不是免检理由。

同一原文的原生对象共用已验证的源渲染，不为每个 Shape 重新导出整本。原生 Shape 和无法解码的媒体，仍通过 `figure_review.py bind-rendered` 绑定真实文件渲染报告及完整对象裁片，再送入视觉大模型。

## 缺陷不能因续跑而消失

初检问题与后续新发现都对照原文保存。新增缺陷台账固定在会话的 `work/reports/image-discoveries.json`，所有终检轮次引用同一台账，不创建新空台账替代旧失败。

已登记图内缺陷而真实图像未变时，不能靠后来的 PASS 清除；只重新编码图片也不算修复。图片初检和每张已完成的终检结果及时保存，中断后不无故重新调用已完成对象。

## 页面与表格

按一两页窗口看实际最终页面，不能只看缩略拼图。每一页保留实际观察；每张实际表格都记录当前对象和所在页面、列宽/跨页/语义结果，而非只处理表格审计候选。脚本校验覆盖和结果绑定，不宣称能独立证明模型看清了图。

手工修改 `overall_status`、图片检查项或文件哈希不能使缺失/失败证据变成有效结果。没有自动视觉接口不等于宿主不能看图；走下述宿主路径。两条路径都不可执行时保留待检查，不能伪造正式检查回执。适配器接入、真实模型识别能力和 Word/WPS 兼容性必须在实际宿主验证；单元测试不代替这些验证。

## 宿主视觉大模型路径

`inspect-initial` / `inspect-repaired` / `inspect-final` 未传 worker 配置时返回任务和真实图片路径，不自动判定通过。Agent 必须使用宿主的**视觉大模型**实际查看列出的全部图片，按任务 `request.json` 的检查结构保存响应，并记录真实模型身份、工具名称、会话/工具调用引用及所查看图片 ID、哈希。用户不需要填写这些记录。

```bash
python scripts/host_visual.py <task.json> <response.json> <tool-log.json>
# 随后重试原来的 inspect-* 命令，程序导入已完成结果，不重新调用模型。
```

`tool-log.json` 至少包含：

```json
{
  "request_id": "从 task 复制",
  "tool_calls": [
    {
      "tool": "真实宿主看图工具",
      "reference": "真实会话/工具调用引用",
      "reviewer": {
        "kind": "vision_model",
        "provider": "实际宿主/供应商",
        "model": "实际视觉模型"
      },
      "images": [
        {"id": "从 task 复制", "sha256": "从 task 复制"}
      ]
    }
  ]
}
```

所有标识从任务复制，所有 image id 必须至少被一次 `vision_model` 调用覆盖。必须来源于实际工具使用，不造日志；本地记录检查只验证覆盖、新鲜度和模型身份，不是防恶意伪造的宿主签名。原失败结果不可覆盖；图像真实修复后生成新任务。

## 修图前与修图后

初检完成后，对需要改图内内容的块执行 `--action image-plan`，从当前真实缺陷获得对象级修复范围；正常图只调整必要布局。修图后执行 `--action inspect-repaired --proposal block-fixed.docx`，**把新像素再次送入视觉大模型**，先检查新图与原图语义，再提交 checkpoint。局部失败不允许靠重复检查同一坏像素消除。

原生 Shape 的局部复查会返回 `native-review.json` 和所需的 `native-review.bound.json` 路径。沿用 `figure_review.py bind-rendered` 绑定当前拟稿的真实渲染及裁片，再继续；不是将无媒体对象直接豁免。正文外对象的 ID 包含部件前缀，例如 `S_header1_F0001`，不要自行拼造 ID。
