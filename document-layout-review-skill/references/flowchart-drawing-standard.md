# 流程图绘制与验收标准

## 本项目图面与题注约束

本规则也覆盖架构图、技术路线图和分层结构图，但不得把无箭头的架构图强行转成有向流程并补造节点/箭头。先查看真正的图像或原生 Shape，不以节点 JSON 的审计结果代替图面检查。

图内文字出框、重叠、裁切必须修；原配色和图形风格正常的部分保留。图片输出只含业务图形，禁止写入“图2.1 …”等外部编号和题注。题注由 Word 独立段落与 SEQ 域承担。检测到已烧录题注时，只清除已确定的题注区域或从可靠源重出图；不能裁掉业务内容，也不能把 Word 页上的正常图题误认为图像内容。

初检、修复、终检按 `caption-and-image-review.md` 逐对象闭环；缺检查或初检硬缺陷未修复，不得通过。模型必须真实查看图片；脚本只验证证据覆盖、哈希与闭环，不会从栅格图片自动推断所有文字边界。


本规则用于业务流程、技术路线、质量闭环、审批流程等常见流程图。目标不是“把所有节点塞进一张图”，而是保证**语义无歧义、箭头可追踪、文字清晰、页面可读**。

## 适用边界

先遵循 `flowchart-rules.md` 的保留原图/独占页路径。下列绘制默认值用于新图或已获准重绘的候选图，不是改造正常原图的理由。修复已有图时，原配色、方框/圆角、边框和字体风格优先保留；仅为消除已确认缺陷做必要调整。

原图中清楚、无歧义的图形约定或斜向连线，不因与下列默认规范不同就强制改形、改线或重绘。

## 1. 图形语义

默认使用下列图形语义，不随意混用：

- 开始／结束：终止符（圆角椭圆／胶囊形）；
- 普通过程：矩形；
- 判断／条件：菱形；
- 子流程：双边框过程框；
- 文档／成果：文档形状；
- 分组／阶段：分组框或泳道，不用普通过程框冒充。

同一张图内，相同语义必须使用相同图形。

## 2. 主流程方向

一张图只选一种主方向：

- `TB`：从上到下；
- `LR`：从左到右。

主流程不得在图中无理由来回折返。回退、重试、整改、复测等循环边必须走主流程外侧回廊，不能穿过主流程节点。

## 3. 判断节点

判断节点必须满足：

- 使用菱形；
- 每条输出分支含义明确；
- 常见双分支使用“是／否”“通过／不通过”“满足／不满足”等中文标签；
- 同一判断节点的分支标签不得重复；
- 标签贴近自己的出边，不得放在两个分支之间造成归属不清；
- 判断节点后的分支应在视觉上立即分开，不能先共用一段线再无标识分叉。

## 4. 连线和箭头

默认采用**正交折线**，不使用任意斜线连接业务节点。

必须满足：

- 箭头从源节点边界出发，在目标节点边界结束；
- 箭头只在目标端出现，方向必须与语义 `from → to` 一致；
- 连线不得穿过任何无关节点；
- 连线不得贴着节点文字穿行；
- 连线交叉默认视为排版失败，应重新布局；
- 两条线不得长距离重叠后又分叉，避免无法判断箭头归属；
- 回路线走图形外围，不从主流程中间穿回；
- 多条线汇入同一节点时，优先分配不同入端口，避免箭头堆叠在同一点；
- 多条线从判断节点发出时，优先使用不同出端口；
- 不通过缩小整图来掩盖连线问题。

对于复杂流程，必须使用 ELK／Graphviz 等具备正交路由和避障能力的布局引擎；不能由模型手工猜坐标。

## 5. 文字

- 节点文字必须完全位于边框内；
- 节点应根据文字实际宽高自动扩展；
- 普通过程框优先控制在 1～3 行；过长内容应拆成更短节点或提高节点宽度；
- 判断问题应简短、可直接回答；
- 分支标签保持短小；
- 最终插入 Word／PDF 后，正文阅读尺寸下仍应清晰可辨；
- 当前页空间不足时，先让“原图 + 图题”独占一页，不为减少页数缩小到难以阅读；仍不可读时再评估必要重排。改横向、改变页面尺寸或拆分子流程必须有模板依据或用户授权。

## 6. 间距

- 节点之间必须留出足够的连线路由空间；
- 分支节点之间应有明显横向／纵向间隔；
- 回路线与节点边框之间保留安全距离；
- 边标签与线、节点、箭头之间均应留白；
- 整张图四周保留页边距安全区。

## 7. 标点语境

流程图文字执行与正文完全相同的上下文规则：

- 中文标题、中文节点、中文分支标签使用全角中文标点；
- 英文节点、英文标识、代码、路径、URL、版本表达和公式使用半角标点；
- 中英文混排按局部语境判断。

示例：

```text
满足条件?      → 满足条件？
否,整改         → 否，整改
API（v1.2）     → API(v1.2)
f（x）＝x＋1    → f(x)=x+1
```

不得为了统一样式把英文／代码／公式中的半角标点改成中文全角，也不得把中文句读标点改成半角。

## 8. 强制验收门

流程图只有同时通过以下三层检查才算完成：

### A. 语义检查

- 节点完整；
- 箭头完整；
- 箭头方向正确；
- 分支标签正确；
- 回路和汇合关系与来源一致；
- 没有擅自新增业务步骤。

### B. 几何检查

必须为 0：

- 连线穿过无关节点；
- 非预期斜线；
- 无法判定归属的连线交叉；
- 箭头指向错误节点；
- 节点文字溢出；
- 节点重叠。

若布局器报告上述任一错误，不允许输出“已修复”。

### C. 最终页面视觉检查

将新流程图放入目标文档，渲染最终 PDF／页面图片后再次检查：

- 正文缩放下仍清晰；
- 图没有超页；
- 字号没有小到难以阅读；
- 图题和图本体间距正常；
- 箭头、分支标签、回路线肉眼可追踪；
- 没有因 Word 缩放重新产生模糊或重叠；
- 原图与新图并排对比，原有良好配色、形状、字体风格和层次没有被无依据改掉；
- 图与图题同页，独占页没有改变页面方向、拉伸图片或遗漏前后正文。

如果 C 不通过，先判断是否仅为页面容纳问题：优先保留原图并调整大小、位置或独占页。确需重绘时保留源风格再调整布局；不得直接换默认配色、压小文字或擅自拆改流程。
