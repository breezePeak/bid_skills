# 最终验收与交付

## 放行条件

按 `SKILL.md` 第5—7节执行。全文块完成；当前候选已实际更新域；全部必需程序审计通过；原文内容和修改范围受保护；所有最终页面、实际表格和图片均有有效检查结果；未解决问题和必需未执行检查均为零。

**有任何业务图片时，每张图必须至少存在一次与真实像素绑定的视觉大模型回执。** 回执必须包含 `vision_model` 身份、实际 provider/model、全部任务 image id 覆盖、真实请求/响应和哈希绑定。OCR、脚本门禁、像素检测、整页排版观察或手填 `pass` 不算图片视觉验收。

块的 `checked` 只表示局部处理完成，不是整份文档已通过。最终入口校验当前分块会话、源文件和候选绑定；后来 reopened 的块、外部改动或规则变化使旧交付结论失效。

## 入口

全部块完成后由 `review_pipeline.py --action final` 生成本轮清单。原有14项审计保留在最终验收，不在每块反复执行；块提交只执行对应内容、格式和域边界检查。模板结构与表格外观分别使用 `stable_template_audit.py` 和 `stable_table_audit.py` 排除经核对等效的样式序列化差异，真实属性差异仍失败。最终复制由 `finalize_review.py` 完成；只复制真正验收的字节，不能将中间候选改名冒充成果。

当前页面观察必须完整，表格覆盖按实际对象清单核对。图片可依据“**真实视觉大模型图内通过证据 + 未变的当前像素 + 当前页面观察**”复用；从未经过视觉大模型的图不允许复用。改变图、缺陷图或不确定图必须执行相应实检。原始凭据不可改写。

`inspection=null`、`pending/uncertain`、模型身份缺失、模型未覆盖任务全部 image id、图片哈希或页面绑定过期，均为硬失败。不得用“12项门禁全绿”“图未修改”“页面正常”跨类推断图片视觉通过。

## 失败处理

确定性或视觉检查失败，集中定位对应块，修复后复查受影响对象及边界。不是重新启动全文修复。相同候选的准备任务可续用；失败步骤须有针对原因的处理才能继续；相同输入及条件连续两次同因失败后不得第三次全量重试，不重复已经成功且输入输出绑定有效的更新域、审计或渲染步骤。

原文、模板、报告和当前图像/页图的哈希缺失或不一致时重新生成相应结果，不更改哈希让记录通过。视觉大模型未实际看图时，保持 `requires_image_review`，不以程序记录齐全代替。

## 交付

最终 Word **只能**由 `finalize_review.py` 在全部门禁通过后复制产生。`work.docx`、`candidate.docx`、`proposal.docx`、`block-fixed.docx` 等中间文件不得直接交付；图片大模型证据不完整时 `finalize_review.py` 必须失败。

同时交付修复 Word 和简短实际修复报告。报告说明位置、原问题、修改及复查，标明实际引擎、实际视觉大模型和验证范围。清单通过与视觉大模型通过分别汇总；Office 退出或清理告警不得隐去，但不使经过输出校验的有效成果被无故重做。Word F9 只能由真实 Word 验证；WPS/LibreOffice 不冒称。

程序入口约束当前技能的交付过程，不宣称已经获得宿主不可绕过的系统级权限 hook。未验证或有阻塞时保留进度并如实说明，不能发送冒充通过的文件。
