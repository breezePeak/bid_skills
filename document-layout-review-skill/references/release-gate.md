# 最终验收与交付入口（清单版本 5）

## 放行条件

先按 `SKILL.md` 第 5—7 节执行修复复查、明确验收和失败闭环。**全部必需审计通过、未解决错误为零、未处理 review/待确认项为零、视觉缺陷为零、必需验证无缺失，才允许交付。** 最新页面、表格和图片必须无漏检，内容保护及修改范围检查必须通过。

“全部审计已运行”“清单版本正确”或“脚本退出码为零”都不是完整验收标准；程序通过但页面明显失衡、文字出框或语义错误，仍不得交付。具体对象标准见 `acceptance-checklist.md`。

## 交付前执行

`review_pipeline.py` 的 v5 清单必须包含当前 `REQUIRED_GATES` 的全部检查，含 `template-effective-format`、`table-layout-template`、`content-integrity`；不以检查数量替代实际结果。初检、修复、终检和续跑使用同一原文、模板与规则。

题注固定**图下表上**；图表原生自动编号须持续刷新，不依赖标题文字/样式显示名，不拼 STYLEREF。真实更新后的序号、域边界、重启及引用均合格；编号修复或引擎恢复指令后按执行说明再次刷新，以最后输出进入验收。不得过滤 `caption-position`、锁域、手填序号或伪造缓存。

Agent 看过完整原图、最终图及全部最新页图，闭合初检缺陷、处理表格 review，且最终标准全部满足后，执行：

```bash
python scripts/finalize_review.py work/review-manifest.json final-visual-review.json --out final.docx --json-out release.json
```

入口核验原文、候选、模板、样式约定、文字规则、内容保护计划、预检及审计报告、图片与页图证据；并对当前文件重新检查关键编号、模板格式、表格布局和原文内容。不能以可编辑记录中的 PASS 代替实际观察与独立检查。

## 失败后必须怎么做

缺少检查、未通过项目、遗漏图片/页面、未处理 review、记录过期、域刷新失败或内容误改，均停止交付并返回 `SKILL.md` 第 7 节：

**记录具体位置与原因 → 修对应对象或执行条件 → 保护/恢复其他对象 → 实际更新域 → 全部必需审计 → 最新文件渲染 → 逐页逐图及语义复查 → 再次判定。**

内容或非目标对象被破坏，先撤销误改再重修；证据过期则重新生成当前证据；不能手改哈希、报告、版本号或错误级别。只验收续跑保持原始 `--source`、原 `--content-plan`、图片初检及有效对象计划，不把候选重新当原文。旧 v4 清单须重新跑当前流水线，不能只改成数字 5。

真实冲突、语义无法确定、源资料缺失或排查后无可执行环境时，保留工作文件并说明具体阻塞，不发冒充验收成果的候选；条件补齐后继续。其他可确定问题由 Agent 继续修，不能因“脚本已经跑过”结束。

## 成果与边界

只交付入口成功生成的修复 Word 和实际修复报告；失败不覆盖已有正确成果，输出不覆盖原文、模板或验收证据。任何后续修改都使旧验收失效，须重新更新、审计、渲染和复查。

脚本验证覆盖、绑定和缺陷记录闭环，不独立证明模型看清图片，也不是宿主级不可绕过的权限 hook。宿主仍允许任意发送文件时须另行限制交付权限；这不降低本技能的实际看图、失败重修和交付标准。Word F9 的实测只能由真实 Word 执行证明。
