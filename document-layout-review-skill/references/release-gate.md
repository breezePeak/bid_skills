# 最终交付入口（清单版本 5）

只交付 `finalize_review.py` 成功输出的 Word 和实际修复报告，不将 candidate 改名交付。

`review_pipeline.py` 必须生成版本 5 清单，含原有编号、文字、模板、表格、图片与实际更新域检查，以及新增的 `template-effective-format`、`table-layout-template`、`content-integrity`。缺少任何必需检查不得输出成果。初检、修复、终检及续跑始终使用同一原文、模板与规则。

Agent 实际逐页逐图检查最新截图，关闭图片初检缺陷、逐项处理表格 review，再运行：

```bash
python scripts/finalize_review.py work/review-manifest.json final-visual-review.json --out final.docx --json-out release.json
```

交付前核验原文、候选、模板、样式约定、文字规则文件、内容保护计划、预检记录、审计报告及页面证据的哈希；再对当前 Word 独立复查标题/题注、模板表格外观、附加文字格式、模板表格布局和内容完整性。不以可编辑报告中的 PASS 代替复查。

图片/页图漏检、缺陷未关闭、记录过期、域更新报告不对应候选、明确指定引擎与实际引擎不符或原文内容误改都不得交付。任何后续修改都须重新实际更新域、审计、渲染和验收。失败不覆盖已有成果，输出不得覆盖原文、模板或验收证据。

旧 v4 清单不能直接交付，须通过新流水线生成 v5。只验收续跑时保留原始 `--source`、`--content-plan`、图片初检及有效对象计划，不重新生成“以候选为原文”的基准。

这不是宿主级不可绕过的 hook。若宿主允许 Agent 任意复制和发送文件，需宿主把交付权限绑定到此入口；本 Skill 不能代替该权限控制。图片结论仍来自真实看图，哈希和 JSON 只证明记录覆盖与绑定，不证明模型看清了内容。

题注基准固定图下表上，模板不能覆盖。题注和更新域门槛包含 `caption_field_guard.py`：域边界完整、固定图/表序列、无标题/样式名/书签参数依赖，实际更新后序号正确且无域错误。不得过滤原核心的题注位置错误。
