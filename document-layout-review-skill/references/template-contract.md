# 模板合同、内容保护与执行接口

本文件说明当前执行入口的职责。默认模板中的示例不能覆盖上传模板；本次已确认用户要求优先。模板决定样式外观；题注位置固定图下表上、自动编号可持续刷新属于先于模板的项目基准。原文件用于内容和原图对照。未确定的样式映射、相互冲突的样表或复杂条件格式要明确阻塞，不从坏文档猜一个格式后记为通过。

## 格式职责

| 入口 | 职责 | 不应承担的工作 |
|---|---|---|
| `template_style_enforce.py`、`template_usage_repair.py` | 模板语义样式、字体/字号、文字规则；复制样式依赖链 | 改写业务内容、替换正常图片 |
| `template_format_contract.py` | 共享继承解析；正文/标题/题注及可映射故事中的附加字符和段落格式修复/审计 | 取代已有字体规则、表格条件外观和实际看图 |
| `template_table_style.py` | 模板表格底色、边框、文字颜色和条件外观 | 按旧文档装饰决定模板 |
| `template_layout_contract.py` | 模板表/单元格对齐、内边距、行规则 | 选择业务合并关系 |
| `table_layout_repair.py` | 表格宽度、列宽及固定几何 | 重设居中、固定内边距、字体、底色或表头 |
| `docx_layout_policy.py` | 调用同一模板布局合同 | 按“技术偏离表”等关键词推导页面方向 |
| `template_caption_policy.py`、`caption_field_guard.py` | 固定图下表上；保留核心全部验收错误；核对独立原生序列与刷新结果 | 让模板颠倒位置，或拼接会随标题变化失效的引用 |

### 共享属性

字体、字号、加粗/斜体、正文黑体例外仍由现有 `text_rules.py` 接口控制。新增模块处理颜色、下划线、高亮、底纹、边框、删除线、大小写显示、文字间距、字符缩放及相关段落属性，修复和检查调用同一个解析器。保留公式上下标、域隐藏等语义属性，不因格式统一粗暴抹掉。

样式依赖按 `basedOn`、`link`、`next` 递归复制；不存在的依赖、继承循环不能静默忽略。生成编号所用的受管样式别名只可映射到明确的模板角色，不可借别名保留旧格式。页眉/页脚/脚注/尾注中可映射样式进入补充审计；图内文字及表格条件格式交由专门检查，不能以“未检查”充当“通过”。这不是所有 Word XML 属性的通用渲染器。

### 题注位置和序号

题注固定**图下表上**，模板仅决定题注字体、字号、段落等外观。旧版 `caption_placement` 配置不再改变位置；即使模板样表把题注放反，仍按图下表上修正。缺少位置示例不需要询问用户。

图、表各自按一级章节从 1 自动递增，不显示章节前缀。使用固定 SEQ 图/表序列及数值层级 `\s 1`，不引用标题文字或样式显示名，不拼接 STYLEREF。保留隐藏章级重置，不将重置绑定到首个图表。

所有核心编号与位置错误都必须保留；不得再过滤 `caption-position`。`field_refresh.py` 在真实更新前验证域结构，更新后验证序号及错误结果；`validate_report`、编号审计和最终交付入口同样重新检查。Office 导出若丢失编号开关，仅恢复源文件已验证的原生指令，原样保留真实引擎结果并记录双侧哈希；禁止用假缓存或锁域掩盖问题。具体回归见 `references/caption-baseline.md`。

## 内容保护

`review_pipeline.py` 在原始文件上建立 `work/reports/content-plan.json`，绑定原文 SHA-256。新题注从源绑定对象计划登记；真实脚注转换从编号阶段回执登记，并再核对原引用范围、标记、原脚注文字和最终脚注文字。计划不是模型可任意填写的业务改写白名单。

`content_integrity.py` 对照原文与候选，保留段落/表格逻辑边界、引用关系、脚注 ID、修订删除文字和其他故事。只规范化明确的排版差异；保护业务数字、负号/小数、公式、URL、路径和代码。

纵向合并通过逻辑单元格展开复核：同一分组的相同重复文字合并后不会被误报丢失；不同文字被隐藏、孤立续接或列跨度不对应仍阻断。是否应合并仍须 Agent 确认语义，程序通过不替代该判断。

`--audit-only` 必须用 `--source` 指回原文，并沿用内容保护计划；不能候选对候选自证合格。无法识别的自定义脚注标记、重组内容或复杂语义变化可能需要定位处理，不能将整个文字保护关闭。

## 入口环境预检

预检发生在文档修改前，包括包完整性、模板规则绑定、目录可写、LibreOffice/pdftoppm 渲染程序、可实际调用的 Word COM 或 LibreOffice UNO。当前渲染入口仍依赖 LibreOffice 和 pdftoppm，只有 Word 并不足以完成这条流水线。

`--field-engine auto` 优先可用 Word，否则可用 LibreOffice UNO；`word`/`libreoffice` 是明确要求，不静默替换。可用 `--uno-python` 指定有 UNO 的 Python。能力探测不等于已经更新域；后续仍调用真实 Office、保存并核验结果。只验收模式要求与候选哈希一致的真实更新域报告；明确要求 Word 时，LibreOffice 报告不能代替。

## 版本 5 门槛

保留原 11 项检查，增加三项必需门槛：

| 门槛 | 检查 |
|---|---|
| `template-effective-format` | 共享附加格式及映射符合性 |
| `table-layout-template` | 表格标量布局是否符合生效模板 |
| `content-integrity` | 原文到最终文件是否发生未允许的内容变化 |

三项同时接入正常修复、只验收续跑与 `finalize_review.py`。最终入口重新运行，而不只相信报告中的 PASS。规则、计划、候选或证据变更使旧验收失效。v4 清单需要重新跑 v5，不得手改版本号或补几个布尔值。

## 图片与宿主边界

沿用逐对象初检、完整原图/局部放大/最终页观察、哈希绑定和缺陷闭环。新模块不声称能自动读出所有图片缺陷，也未实现宿主级权限钩子。没有实际看图，不得写视觉通过；宿主仍允许任意发送文件时，需宿主另行限制可交付文件的来源。
